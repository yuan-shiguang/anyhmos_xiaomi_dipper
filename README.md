# 小米8（dipper）· HarmonyOS NEXT

[English](README.en.md) · [构建说明](docs/BUILDING.md) · [源码索引](docs/SOURCE_MAP.md) · [测试记录](docs/VERIFICATION.md) · [来源与许可](docs/PROVENANCE.md)

这是小米8（**dipper**）的 HarmonyOS NEXT 移植项目。通过兼容层适配显示、触控、音频和无线等硬件。移植仍在进行，代码按本机参数整理，硬件结论以真机日志和[测试记录](docs/VERIFICATION.md)为准。

其他机型也可以参考部分的代码和思路；通用的做法是把华为的 system、vendor、sys_prod 以及本机的 vendor_dlkm 打进 super 刷入，再提取本机的 boot、vendor_boot、init_boot 改挂载点，做出 USB 串口后按日志修开机。米 8 走不了这条路：它没有 `super`、`vendor_boot`、`init_boot`，Android 侧是单槽静态分区，只有引导链是 A/B。所以这里的方案是把鸿蒙的 system 直接写进 3 GiB 的 `system` 分区、vendor 写进 1 GiB 的 `vendor` 分区，兼容层载荷放在 832 MiB 的 `cust` 分区，开机时从 `/cust/compat` 挂到 `/compat`。分区实测数据和取舍理由见[分区布局](docs/DEVICE-PARTITIONS.md)。

本机主要参数：骁龙 845（sdm845，Adreno 630），6.21 英寸 AMOLED 1080×2248、60Hz、单 DSI，3400mAh 电池（18W 快充，无无线充电），Wi-Fi 5（802.11ac，2.4/5GHz，80MHz），蓝牙 5.0，底部单扬声器加听筒，USB-C 音频，无 3.5mm 耳机孔，后置指纹。

仓库提供各功能当前使用的源码、启动配置和构建工具。系统还有不少功能需要完善，具体进度见下表。

## 功能进度

下表描述兼容层当前的实现范围和已知问题。硬件相关的验收状态以[测试记录](docs/VERIFICATION.md)为准，未在真机复核的项目按未完成处理。

| 功能 | 当前情况 | 待完善内容 |
| --- | --- | --- |
| 启动与桌面 | 兼容层可以接管启动流程、进入桌面、打开窗口并截取系统画面。 | 开机耗时较长，部分应用和服务仍有等待、卡顿或崩溃，长期稳定性需要继续改进。 |
| 屏幕显示 | 显示后端按 1080×2248 单 DSI 面板初始化，并按连接器实际暴露的平面数选择单平面或双平面扫描输出。 | 亮灭屏、休眠唤醒及长时间使用的稳定性需要真机复核，黑条、白屏等异常仍需逐项排查。 |
| GPU 与刷新率 | 已接入 Mesa/Turnip/Zink 图形支持，显示模式为 1080×2248、60Hz，使用内核原生 GPU 调频。 | 面板只有 60Hz，不涉及高刷新率；图形性能、格式兼容和画面同步仍需优化。 |
| 触控与操作响应 | 由官方内核内置 ST FTS（`fts@49`）/ mXT640U 驱动以标准多点触控上报，兼容层只把 evdev 节点交给多模输入，不再需要厂商算法桥。 | 触摸采样、多点触控、边缘操作及休眠恢复需要真机复核。 |
| 亮度 | 手动亮度调节可用。 | 自动亮度、最低亮度和休眠后的恢复需要继续测试。 |
| 电源键与音量键 | 短按电源键可以熄屏、亮屏，长按可以打开关机菜单；音量键已接入系统。 | 锁屏、休眠及连续操作时的按键行为还需全面测试，深度休眠功耗尚未评估。 |
| Wi-Fi | 驱动用官方内核内置的 qcacld-3.0（`CONFIG_QCA_CLD_WLAN=y` + icnss），不是 qcacld-2.0。兼容层把 `firmware_class.path` 指向设备 vendor 分区里的 `firmware/wlan/qca_cld`，只设路径不拷贝；vendor 缺文件时才回退到 ramdisk 载荷。 | 米 8 的 WLAN 校准文件必须在 vendor 分区里真实存在，否则 `wlan0` 不出现。内置驱动在用户态启动前已经 probe 过一次，运行时写路径只对模块化加载或重新 probe 生效，内置场景还需要在 kernel cmdline 上加 `firmware_class.path=/vendor/firmware`；mac 地址、5GHz、功耗和长时间连接也需要真机复核。 |
| Wi-Fi 协议显示 | 状态栏可以显示实际连接的 Wi-Fi 5 标识。 | 本机不支持 Wi-Fi 6/7，相关标识不应出现，需要回归确认。 |
| 蓝牙 | 部分可用，已实现开关和附近设备发现。 | 开启时存在短暂卡死、系统界面重启的问题。配对、蓝牙耳机通话与播放、键鼠和 BLE 尚未完整验证；设备不支持星闪。 |
| 扬声器与音频 | 播放后端改成 sdm845 的 tinyalsa 实现：静态链接的 `dipper-tinyalsa-server` 直接对接内核 PCM 节点，并按下行路由打开 `SLIMBUS_0_RX`；音量在用户态做 Q15 定点缩放。 | 米 8 没有 `/dev/agm`，sm8550 的 PAL/AGM 后端在本机不可用；新后端的实际出声、TAS2557 功放的 Program/Configuration 下发（原厂由 audio HAL 完成）以及录音的上行路由都需要真机复核。 |
| 视频与图片 | 部分软件解码路径可用，部分系统及第三方应用能够显示视频和图片。 | 硬件视频解码尚未完成，部分格式或应用仍可能播放失败、卡顿。 |
| 输入法 | 可以弹出键盘并输入内容，已用于输入 Wi-Fi 密码。 | 更多应用、网页输入框和多语言场景需要测试。 |
| 第三方应用与预装应用 | 已接入 preload 应用安装，修复部分应用启动时的“应用数据解密中”拦截，抖音等应用能够进入并显示内容。 | 部分应用仍停留在启动画面或闪退，登录和依赖网页的功能存在问题。 |
| 用户数据 | 整个 userdata 分区直接挂载为 `/data`，保留首次开机向导。新代码支持正常格式化的 ext4，不需要指定 UUID 或手动创建标记。 | 新挂载逻辑已通过隔离镜像测试，尚待真机重刷确认；升级和回滚流程需要完善。 |
| 电池与充电状态 | 可以读取真实电量和充电状态，系统显示不再固定为 100%。 | 充电状态变化、温控、18W 快充、续航和待机耗电需要继续测试。 |
| 时间同步 | 联网时间同步已可用。 | 离线时间、时区和部分界面的时间显示仍有不一致。 |
| USB 调试 | 提供命令执行、文件传输和截图工具。 | 重启或 USB 状态变化后仍可能失去响应，调试连接的可靠性需要继续改进。 |
| A/B 启动 | 可以在桌面启动完成后标记本次启动成功。 | 完整 OTA 和 A/B 升级流程尚未实现。 |
| 网页与 WebView | 尚未修好。 | 部分网页无法打开或显示空白，抖音网页登录仍可能一直加载。 |
| 安全与加密 | 有软件兼容实现，支持部分系统服务和应用运行。 | TEE、硬件密钥、锁屏凭据及 HUKS 仍未完整适配，不能提供原厂同等的安全保障；应用市场加密版应用不能解密使用；支付、DRM 等功能未验证。 |
| 相机、麦克风、传感器及指纹 | 尚未完成。 | 相机成像、录音、传感器和后置指纹需要分别适配和测试。 |
| 跨设备协同 | 尚未完成。 | 设备发现、连接及跨设备功能仍需适配。 |

## 各分区的改动

| 分区 | 改动内容 |
| --- | --- |
| `boot` | 使用 4.9 官方内核（sdm845），保留鸿蒙进程通信所需的接口；硬件参数按小米 8 的 4.9 官方内核源码核对。容量 64 MiB，放内核加精简启动内存盘，余量约 21 MiB，装不下兼容层。 |
| `system` | 写入鸿蒙的 system 镜像，开机按 `by-name` 直接挂静态 ext4，不走 LP metadata 与 dm-linear。分区 3072 MiB，构建时会校验体积，超限直接报错而不是截断。 |
| `vendor` | 写入鸿蒙的 vendor 镜像，同样按 `by-name` 直接挂载。分区 1024 MiB。 |
| `cust` | 存放兼容层载荷（源码接口、配置、音频与固件文件），开机后挂到 `/cust`，再把 `/cust/compat` 挂到 `/compat`。分区 832 MiB，是这份整包里唯一可以自由支配的静态分区。 |

## 源码目录

- `compat/`：按功能划分的兼容层源码、接口和共享依赖。
- `runtime/`：启动脚本与运行配置。
- `patches/donor/`：鸿蒙原系统库的补丁配方，包含文件哈希和修改位置校验。
- `external/`：依赖的上游源码信息、内核与 Mesa 补丁及许可。
- `tools/`：构建与源码校验工具。
- `output/`：电脑端调试、传输、截图、备份与恢复脚本。
- `tests/`、`analysis/`、`evidence/`：测试用例及去除私人信息的测试记录。

每个功能保留当前使用的实现和必要依赖。详细文件说明见[源码索引](docs/SOURCE_MAP.md)，文件清单和校验值见 `SOURCE-SELECTION.json`、`SOURCE-MANIFEST.json` 与 `SHA256SUMS`。

## 构建与使用

构建环境使用 WSL。请先按[构建说明](docs/BUILDING.md)准备 SDK、上游源码和链接依赖，再查看可构建的目标：

```sh
python3 tools/build_current.py --list
```

UserIAM 相关组件通过 `tools/build_useriam.py` 构建。仓库目前提供兼容层及相关组件的构建流程，完整 ROM 仍需要另行准备系统镜像、固件和应用等内容。这些文件不随源码分发。

系统内的 USB 调试使用 `output/` 中的工具，命令需要依次执行。刷入前请备份本机的 `boot`、`system`、`vendor`、`cust` 四个分区，并核对机型和镜像校验值。测试范围和记录见[测试文档](docs/VERIFICATION.md)。

全新安装时，userdata 需要先在 Recovery 中格式化为 ext4。启动程序会挂载整个分区并创建必要目录，不要求特殊 UUID 或初始化文件，也不会自动格式化。只执行擦除而未创建文件系统时无法启动。详见[数据分区说明](docs/USERDATA.md)。
